# Проба приоритета времени у предварительного Мастера

Запуск из корня Unity-проекта с PowerShell 7, Git и .NET 8.

```powershell
pwsh -NoProfile -File Tools/MasterTimingTrial/Run.ps1 -Output "$env:TEMP/master-timing-ab.json"
pwsh -NoProfile -File Tools/MasterTimingTrial/Run.ps1 -IncludeC -Output "$env:TEMP/master-timing-abc.json"
```

Сценарий извлекает Core и каталог трасс из коммита `2230406` во временный каталог. A компилируется из этих исходников. B использует [патч итогового выбора](master-time-first.patch), а C добавляет к B [патч промежуточного выбора](master-frontier-time.patch). Каждый процесс готовит собственный кэш и проверяет повтор из него. Сценарий сверяет хеши исходников и оставляет результаты обеих или трёх сборок во временном каталоге.

Матрица покрывает «Длинные серии» и «Быстрые связки», оба готовых управления и оба положения переключателя разгона. Мастер проходит три холодные попытки с seed 12101–12103 и тёплую с seed 12102 из банка seed 12101. Остальные четыре уровня проходят по одной холодной попытке на ячейку. Сценарий требует точного совпадения их записанных траекторий, команд, исходов и кэша. Весь ввод проходит через `RaceRunner` после штатного отсчёта.

JSON хранит личный финиш, удары, ловушки, IDs положительных наград, ленту, кадры применения команд, поиск и замеры подготовки. Отдельный прогон считает полные кандидаты до итоговой сортировки. Подготовка измеряется в .NET, процессы запускаются последовательно, каждый после одного прогрева. Показания процессорного времени коротких порций округляются системными часами.
