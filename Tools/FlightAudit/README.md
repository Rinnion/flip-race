# Независимый FLIGHT audit

Отдельные аналитические проверки новой модели полёта через настоящие `RaceSimulation.Press` и `Advance`. Runtime не изменяется. [Матрица до реализации](../../Verification/FLIGHT-AUDIT-PLAN.md), [gates](../../Verification/FLIGHT-TASKS.md).

**PASS: 68 928 утверждений / 1864 игры** на frozen Core `f1c3dad2…` и FlightSettings `1e577574…`. [Итоговый отчёт, SHA и standalone](../../Verification/FLIGHT-PHYSICS-AUDIT.md). Этот результат не является браузерной или release-проверкой4.3.0.

Проверяются 12 сочетаний первого действия, закона и повторов; обе исходные стены; крайние g/u, скорости/высоты линейного прыжка; шесть dt вплоть до100. Oracle длительности/вершины вычисляются по формулам. Есть полный measurement после повторов, скрытые неактивные значения, реальные landing/walkoff/departure, линейная стена до вершины и одновременно с ней, interrupted collision и незавершённый полёт на финише/реванше.

Для зеркального обычного прыжка без повторов исходный потолок недостижим из стандартного floor-spawn с теми же правилами. Fixture сначала достигает потолка настоящим Flip, затем **на неподвижной опоре до тестируемого Press** заменяет только ссылку на immutable настройки. То же используется для подготовки каменной опоры. Координаты, скорость, заряд, support и результат не подставляются. Это установка начальных условий численной пробы, не проверка возможности менять физику в пользовательском заезде. Неподвижный второй игрок не используется вместо проверки обеих половин: тестируемые действия выполняются для обоих.

Некоторые fixtures используют широкую допустимую landing-метку на синтетическом камне, чтобы отдельно проверить вертикальный цикл и совпадение wall/apex без требования повторно попасть в узкую авторскую метку. Геометрия игровых участков этим не меняется. Recovery доказывает корректность прерванного измерения, а не прохождение произвольных ошибочных маршрутов.

Из корня проекта, новый процесс PowerShell7:

```powershell
pwsh -NoProfile -File Tools/FlightAudit/Run.ps1
```

Или .NET10 без сторонних пакетов:

```powershell
dotnet run --project Tools/FlightAudit/FlightAudit.csproj -p:UseAppHost=false
```

`Run.ps1` компилирует текущие `Assets/Scripts/Core/*.cs` и файлы этого harness через `Add-Type`; повторный запуск выполняется в новом процессе, чтобы не переиспользовать уже загруженные типы. Итоговый отчёт сопоставляет результат с конкретными SHA исходников. При последующих изменениях Core старый PASS не считается подтверждением новой версии без повторного прогона.
