# Bot diversity UI integration check

After the integration owner freezes Core, Presentation and Web sources, run from `flip-race-unity`:

```powershell
./Tools/BotDiversityUi/Run.ps1 | Out-File -Encoding utf8 Verification/bot-diversity-ui.json
```

The harness retains the original BotUi actual Update/Pointer/menu/controller checks: 1,200 setup configurations across five tracks, two presets, five levels, two cameras, four viewport sizes and three DPRs; 100 full physical races; human A/one BR56 paw, L/S/K rejection, nine-point touch/mouse suppression, hold edges, pause/resize, custom gating and legacy mode transitions. Production methods are not replaced. Native environment aliases and selection texture acquisition are the existing managed seams.

Every actual menu apply and result retry is compared with an independent fixed-seed `BotPlanShuffle` model. The check requires exact key-local sequence, signature, plan index, arbitrary attempt seed and tape; it requires an observed index that differs from attemptSeed modulo count. Mixed menu/retry/changed-key sequences in two UI instances reproduce exactly. Signature and timing bags exhaust without early or boundary repeats; Master keeps its100% signature while timing plans vary. Opening/closing a menu, pausing, resizing and countdown do not draw or write preferences.

Selection-order stress tests use explicit synthetic terminal fixtures to avoid simulating hundreds of redundant races. Repeated input fixtures reconstruct the same selected plan through the real factory without drawing another plan. These fixtures are counted and labeled in the output; full physical terminal reachability is checked separately by the100 actual Update races. This is managed evidence, not native rendering, browser interaction or a physical phone test.

The Run script records source hashes and rejects source changes during its execution. No run should be claimed until the new catalogue and session selection architecture are integrated.
