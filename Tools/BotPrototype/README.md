# Bot plans, export and runtime verification

Run from the Unity repository. These offline .NET8 tools compile production Core without Unity dependencies.

- `dotnet run --project Tools/BotPrototype/FirstRoutes.csproj -- --levels`: fixed catalog and finite libraries for Long/Short/Flow (239 plans).
- `dotnet run --project Tools/BotPrototype/ComplexRoutes.csproj -- --levels`: Cascade/Mixed (104 plans). Original `p` is actual terminal distance; runtime evidence uses explicit terminalDistance.
- `dotnet run --project Tools/BotPrototype/ExportCatalog.csproj`: compare all343 production plans and50 libraries bit for bit with the reports;16592 checks, catalog IDs/hashes, copies, supported presets and signed seeds. `--generate` regenerates only the C# catalog from unchanged accepted reports; it is not online calibration.
- `dotnet run --project Tools/BotPrototype/RuntimeCheck.csproj`: actual production BotRaceController replay against an independent ordinary participant. Every observed Advance(dt) and Press is replayed immediately; complete public personal fields, nested events, ordered effects and ID sets are compared.343plans×2cameras×3frame schedules plus20fixedseed×50libraries×2cameras =4058 scenarios. Pauses/invalid delta,700 successful human full routes, independent human inputs,10 simultaneous-order proofs, all-terminal continuation and frozen personal outcome margin are included. `--smoke` is a small development subset, not delivery coverage.
- `dotnet run --project Tools/BotPrototype/CascadeBound.csproj`: historical audit of the original overstrict Constant-finishes-every-plan requirement. It proves why that requirement was clarified; it is not a current product blocker.
- `node Tools/BotPrototype/VerifyHttp.mjs http://127.0.0.1:4222/ http://127.0.0.1:4223/ http://127.0.0.1:4184/`: compare actual HTTP bytes with the final5.2 manifest and accessibility/version branch.

Reports are Verification/bots-{first,complex}-levels.json and bots-runtime-check.json/.txt. The representative bots-runtime-tape.json is the actual observed sequence and is replayed a third time. Repeated Probe.Run executions in calibration reports are simulationRuns, not a complete recorded action replay. Numeric state replay error0 refers to the identical actual call sequence; separate frame/reference comparisons are tolerance based (maximum observed terminal time error7.06e-10s, distance1.56e-7units). A high field-comparison count is not a count of independent games.

Core tools do not prove native rendering, browser accessibility, physical touch or player enjoyment. Tools/BotUi/README.md describes actual managed Update/Pointer checks; final browser/package evidence and independent acceptance are in Verification/V5-BOTS-STATUS.md. Calibration accuracy and ordered means use full Lagger routes; Constant records honest actual outcomes, including elimination, without filtering seeds. Source contract: ../flip-race/docs/flip-race-v5-bots-delivery-2026-10-28.md. No physical state is injected by the runtime checker.
