## Начальные профили и независимые ориентиры

Значения реализованы и независимо сверены с движением: [14 649 проверок TUNE-01](TUNE-CONTROLS-AUDIT.md). Путь центра D=212; ускорение действует симметрично, толчок направлен к выбранной поверхности. Численная проверка не заменяет браузерный G1.

| ID | a, ед/с² | Начальная скорость u, ед/с | Расчётный обычный перелёт, с | Центр y / vy через 0,2 с от пола |
|---|---:|---:|---:|---|
| base | 662,5 | 0 | 0,800000000000 | 212,75 / −132,5 |
| gravity | 1000 | 0 | 0,651152823844 | 206 / −200 |
| impulse | 662,5 | 140 | 0,616118947844 | 184,75 / −272,5 |
| combined | 1000 | 140 | 0,526033032214 | 178 / −340 |

Независимые формулы: `q(t)=u·t+a·t²/2`, `v(t)=u+a·t`, `T=2D/(u+√(u²+2aD))`. После повтора в момент τ исходящие q/v сохраняются, меняется только знак ускорения. Для возврата без другого касания `s=(v+√(v²+2a·q))/a` после повтора.

Минимальный подскок при немедленном повторе с толчком: `u²/(2a)` — **14,79245** единицы у impulse и **9,8** у combined. Такие профили не допускают произвольно малый подскок; геометрию нельзя автоматически считать одинаково достижимой по прежним координатам.

Проверить все места применения a: движение, surface/turn horizons, камни, кольца и отображение. Неверная поверхность обнуляет скорость и уводит обратно без нового толчка/заряда; repeat/recovery/pause не применяют departure impulse. Clone/rematch сохраняют выбранный профиль, сброс очищает движение.

## Приоритет мгновенного ускорения и учёт времени

| Состояние до подбора | Ожидаемый результат |
|---|---|
| Нет эффекта | Немедленно 330 на полные 0,6 с движения |
| Активный boost, включая обычный, и ожидающий slow | Ещё 0,6 с непрерывного ускорения при множителе 1,5; ожидающий slow не вклинивается |
| Активный slow с отработанной частью | Остаток slow сохраняется; instant действует сейчас, затем продолжается тот же slow, затем прежняя очередь |
| Повторный instant | Продлевает ускоренное движение; не умножает скорость сверх 1,5 и не теряет suspended-эффект |
| Подбор и удар/пауза | Контакт учитывается один раз; заморозка не расходует active/suspended/queued эффекты |
| Финиш до полного расходования | Учитываются только реальные пройденные расстояния и уже отработанные части всех эффектов |

Главный риск исходного учёта: `BoostElapsed/SlowElapsed` читают только `ActiveEffect`. После перемещения частично отработанного slow в очередь эта часть не должна пропасть из времени финиша. Нужен полный учёт отработанного движения, независимо от текущего места эффекта; при завершении нельзя посчитать ту же часть повторно.

Реализованный TUNE-02 учитывает остаточную отработанную часть по active и pending с отдельным credit завершённых pulses. [Независимый аудит](TUNE-INSTANT-AUDIT.md) подтвердил 7 824 утверждения / 384 игры, включая этот риск и повторное прерывание. [Engine-прогон](TUNE-ENGINE.md): TUNE-01/02 **13 сценариев / 1009 утверждений**, прежние V1/V2/V3/V4 и JS differential прошли.

Неизменённый `Tools/TrackProofV4` повторно запущен root на новом Core: **17 221 проверка / 244 состояния восстановления**. Старые маршруты сохранили результаты: безопасные всех трёх режимов — 20 с без эффектов, ideal — 18,8 с / 4+, поспешный — 19,4 с / 3+ / 1−, поздний — 19,1 с / 3+. Новая Tune-геометрия проверена [отдельно](TUNE-GEOMETRY-AUDIT.md): safe 21,0 / ideal 19,2 / trap 19,8 с на каждом профиле, без столкновений; все эффекты отработаны.

Конкретный oracle без ручной подстановки состояния: длина 55, отрицательное кольцо на старте, instant с центром x=42 и суммарным радиусом 20. После **0,2 с slow** герой проходит 22, подбирает instant; ещё **0,1 с boost** проходит 33 и финиширует. Правильное фактическое время **0,3 с**: `55/220 + 0,5·0,2 − 0,5·0,1`. Slow остаётся suspended с остатком 0,4, boost отработал только 0,1. Формула только по active ошибочно дала бы 0,2 с.

Дополнительные проверки: повторное прерывание того же slow, мгновенный бонус при непустой очереди, сохранение порядка обычных наград, отдельные счётчики наград и завершённых частей, no-double-credit, независимость игроков, отмена pending после последующего удара и доступность ещё не тронутых колец из 4.0.1.

## Геометрия и браузер после G2

- На каждом профиле реальным движением подтвердить безопасный путь без air-repeat и идеальный сбор с повтором. Различия подготовленной расстановки записать явно.
- Проверить ранний/поздний подбор над камнем: бонус меняет горизонтальную скорость, но не высоту, вертикальную скорость или защиту от удара.
- Сохранить разные высоты камней, быструю связку и заранее видимую ловушку; после ошибки остаётся достижимый выход без обязательного следующего удара.
- Для финишного ускорителя считать запас **от фактического контакта**, а не центра рисунка. Полные 0,6 с при 330 требуют 198 единиц; активные/приостановленные/ожидающие эффекты могут потребовать большего запаса.
- Подготовленный идеальный маршрут заканчивается с отработанными наградами; отдельный искусственный короткий маршрут проверяет честный частичный эффект.
- Браузер проверяет оба игрока, выбор профиля, заметный pickup, движение, mobile layout, версию, паузу и реванш. Финальный manifest/ZIP — только после финальной сборки.

Delivery не меняет runtime, не запускает Unity и не делает commit. Независимые новые harness сохраняются отдельно от исторических аудиторов.
