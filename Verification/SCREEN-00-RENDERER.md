# SCREEN-00: seam общего поля

21 октября 2026 года. Ограниченный первый renderer seam для сравнения с существующими двумя полями. Core, трассы и профили не изменены. Настройки входа, области касаний, оверлеи и сборка принадлежат отдельной интеграции root.

## Интерфейс

```csharp
var shared = artwork.DrawSharedWorld(w, h, game, time);
CorridorArtwork.Geometry p0 = shared.Player(0);
CorridorArtwork.Geometry p1 = shared.Player(1);
// Caller draws both mascots at these exact origins.
artwork.DrawSharedPersonalForeground(w, h, game, 0, time, p0);
artwork.DrawSharedPersonalForeground(w, h, game, 1, time, p1);
```

`CorridorArtwork.SharedFieldGeometry` содержит `View`, `Player0`, `Player1`, `Player(int)`. `SharedFieldView` — чистый readonly struct без Unity: `Create`, `WorldX`, `WorldY`, `PlayerX`, `PlayerY`, `IsPlayerVisible`; public поля `Width/Height/Top/Bottom/ScaleX/ScaleY/CameraLeft/AnchorX/LeaderCapX/Gap`. Методы личных наград: `RewardState`, `MarkerAvailable`, `ObjectVisible`. `DrawPersonalBadge(x,y,slot,size)` подходит и для отдельного личного UI в его текущей матрице.

## Что рисуется

- Один фон, один набор препятствий по настоящим `ObstacleGeometry` bands, одна копия каждой награды, одна лента. Удар любого игрока не влияет на яркость общих камней и ворот.
- Одинаковые физические X/Y дают одинаковый экранный центр героя. `MirrorX=false` для обоих. Нет личного отражения, разделения по дорожкам, смещения совпавших героев или отдельного вертикального bob центра. Внутренние позы/лапки/шарф и ориентация полёта сохраняются. Размеры объектов и минимальный радиус7.5 соответствуют прежней lane; малый экран не увеличивает коллизии.
- Лаванда/круг закреплены за игроком0, персик/ромб — за игроком1. На награде фиксированные позиции этих знаков; исчезает только знак уже коснувшегося игрока. Pending не считается Available, Failed не восстанавливает знак. Тип и яркость самого бонуса не меняются от контакта второго. При обеих недоступных наградах объект может исчезнуть; физическая посадочная rail остаётся всегда.
- Pending сам по себе не создаёт шлейфа ускорения: шлейф читает только действующий `BoostRemaining`/`FinishBoost`. Личные замедление, удар и реакции не изменяют общую геометрию.
- После отрисовки героев два разных контура и две метки сохраняют обе личности при точном совпадении. Само раскрытие текстур при совпадении выполняет caller; renderer не меняет их координаты.
- При первом индивидуальном финише не добавляется конфетти на всё поле. Праздничный foreground разрешён после штатного `game.Phase == "finished"`; личный экран результата также должен оставаться под контролем caller.

## Камера

Горизонтальный масштаб строго прежний: `(W − clamp(.19W,62,195) −20) / max(1080,1.28W)`. Он не зависит от высоты поля. Общая середина находится на `.19W`; cameraLeft берётся как максимум midpoint-anchor и leader-`.45W`. Camera input ограничен `[0, Track.Length]`, cameraLeft не превышает `Length − AnchorX/ScaleX`. Поэтому лидерский предел действует сразу, без запаздывающего сглаживания; финишировавший не увозит камеру за трассу.

`IsPlayerVisible` относится к **центру**, а не к последнему пикселю спрайта: X внутри0…W. Отставший может покинуть экран до достижения лидером45%; `Gap` возвращает настоящий разрыв. API намеренно не приклеивает героя к краю. Указатель и замеры длительности вне кадра выполняет root. Большой отрыв остаётся риском выбранного кадрирования, а не решённой этим индикатором задачей.

## Проверка и freeze

`dotnet build Tools/FlightUiCompile/FlightUiCompile.csproj -c Release --nologo`: renderer компилируется. Первая компиляция seam —0 ошибок/0 предупреждений; после появления незавершённой root-интеграции остаются3 CS0649 о её session flags, ошибок0. Прогон Unity/браузера не выполнялся этим автором. Независимые pure-camera и reward-state проверки выполняют engine/delivery; их результаты записываются отдельно.

Существующий `Draw` не менялся. Публичный `DrawForeground` передаёт прежние mirror/confetti аргументы выделенному private helper; shared wrapper передаёт отсутствие mirror и откладывает общие конфетти.
