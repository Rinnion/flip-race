## Независимые числовые ориентиры

FastFlip: `t(d) = (sqrt(35² + 2*2700*d) − 35)/2700`; полный перелёт центров 212 — **0.38352798957670875 с**; противоположная посадка на стандартную грань — `t(164) = 0.3358199493051994`, на крупную — `t(120) = 0.28546110995621027`. Воздушные повторы отсутствуют. Неактивные 300/530/112 не могут заменить эти величины.

Старое центральное закрытое окно `[60,180]`, width20 не проходит FastFlip даже при 330: времени внутри допустимой полосы хватает только на 41.112 единицы X при требуемых 48. Кандидат `[12,228]`, width8 имеет локальную половину окна около 63.16 мс при 220, но не проходит при 110. Это аналитическое ограничение, не готовая рекомендация финальной расстановки. Узкая посадка оставляет от центра до края `32/330 ≈ 96.97 мс`; продолжение обязано допускать естественный сход вместо обязательной реакции за это время.

## Критерии финального аудита

| Область | Независимая проверка |
|---|---|
| Короткий участок | Safe/full/trap обеих физик; настоящая landing на 64×48; before/after; gate; первая/вторая награда цепочки отдельно и вместе; изменившаяся скорость после первой награды; FastFlip нажимает второй раз только после реальной опоры |
| Полные трассы | Три трассы × два профиля × шесть dt; safe36/0наград/0ударов, full33.2/9ordinary+finish/0negative/0ударов, реальный trap; обе половины и разные маршруты соперников |
| Окна | Каждый safe input отдельно ±60 мс реального времени; измерение окон наград; не подмена временного сдвига фиксированным X при меняющейся скорости; совместные ошибки не объявляются покрытыми одиночной проверкой |
| Восстановление | Ошибки каждого ввода → первый фактический hit → оставшаяся recovery +150 мс реакции → допустимые действия этого профиля; достичь следующего trailing+radius, а не остановиться до нового препятствия |
| Чистый finish | Геометрическая верхняя граница release для всех 11 обычных эффектов, варианты порядка/подмножеств; пустые active/queue/pending до финальной цели; попадание/промах дают разницу 0.1 с в реальном времени обоих назначений игроков |
| Воспроизводимость | Финальные SHA Core/Tracks/стенда; отдельный stdout; сохраняются старые fixture/RED и исторические отчёты; браузер подтверждает финальную геометрию, не прежнюю кандидатную сборку |

Для универсального хвоста используется независимая консервативная оценка: каждую `.6` сек обычную награду считаем как 198 единиц обслуживания при максимальной скорости330; `F = max(F, latestReleaseX) + 198`. Пропуски и отмены уменьшают объём; recovery одновременно замораживает X и часы эффектов. Более точный ledger использует 198 для positive и 66 для negative; preemption не меняет суммарную работу. Для D3 все 2¹¹ подмножеств дают conservative completeX 7820/7860/7820, точный weighted 7688/7728/7688 до target7876. Это **условная оценка старой геометрии**, а не доказательство новых расстановок; после каждого перемещения награды границы пересчитываются. Полный перебор подмножеств не утверждает, что каждое подмножество физически достижимо.

Полные новые трассы, окна и восстановление закрыты последующим [итоговым аудитом](MODES-AUDIT.md). Браузер/Web/ZIP — отдельный gate05 в [задачах](MODES-TASKS.md). Физические телефоны и iframe этим Core-стендом не проверяются.
