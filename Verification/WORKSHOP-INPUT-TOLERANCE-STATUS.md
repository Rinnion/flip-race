Основной чат координирует и принимает результат. Семантика обсуждена на Astra/high; backend/UI и независимая проверка — Sol/high, поиск — Sol/medium. Игровой Core не менялся.

## Зафиксированные границы

- «пп» в исходном описании трактуется как миллисекунды (согласовано предыдущим ответом). Ровно 13 проб, включая ноль. Нет переупорядочивания команд, совпадения с соседом и отрицательного времени. Минимум 100 мс не запрещает геометрическую пробу: короткий получившийся интервал выводится отдельно.
- Порог после посадки остаётся информацией, не классификацией сложности. Не выводить общую сложность трассы из одного маршрута. Пороги темпа — пользовательские рабочие ориентиры, не физиологическая норма.
- Проба сдвига проверяет отсутствие штрафных столкновений на затронутом участке, принятые команды, настоящую опору после изменённого действия и достижение X окончания исходного манёвра. Если действие стало частью предыдущего полёта, начало участка — его взлёт. Если исходный полёт уже с ударом/без окончания, это явно диагностируется, а не выдаётся за чистый запас.
- Пропуск: до момента следующей исходной команды, строго до её исполнения; для последней — финиш/лимит. Успех подписан «Без удара до следующей команды», не «нажатие лишнее».
- Пробы не требуют сохранения наград или общего финиша. Локальный успех не гарантирует полное прохождение. Разрывы в допустимых точках не склеиваются в непрерывное окно.

## Контракт API для параллельной реализации

`POST /api/input-tolerance`: прежние `json,profile,warningDuration,axis,inputs,surfaceRunSettings` плюс `inputIndex` (нулевой). Ответ:

```json
{
  "status":"ready",
  "message":"",
  "inputIndex":1,
  "stepMs":50,
  "spanMs":300,
  "attempted":14,
  "complete":true,
  "stopReason":"completed",
  "baseline":{"inputs":[0,1.1],"inputTime":1.1,"startTime":1.1,"endTime":2.1,"endX":470},
  "probes":[{"offsetMs":0,"omit":false,"status":"safe","message":"","inputTime":1.1,"startTime":1.1,"endTime":2.1,"endX":470,"collisions":0,"minimumIntervalMs":1100,"botCompatible":true}],
  "omission":{"offsetMs":null,"omit":true,"status":"safe","message":"Без удара до следующей команды","inputTime":null,"startTime":1.1,"endTime":6.0,"endX":1500,"collisions":0,"minimumIntervalMs":null,"botCompatible":true}
}
```

`status` отчёта: `ready|unsupported`; статус пробы: `safe|collision|rejected|invalid|incomplete`. Не выполненные из-за бюджета пробы `incomplete`. Поля времени/позиции пробы nullable для недопустимых. `attempted` — только завершённые вычисленные пробы (не invalid/incomplete). 10 секунд отменяемого бюджета.

`POST /api/input-tolerance/preview`: тот же запрос плюс `offsetMs` (−300…300 кратно 50) и `omit` (false по умолчанию). Ответ `{ "probe": {...}, "samples": [Sample...] }`, с проверенной частью пробной траектории (от старта воспроизведения или начала затронутого участка). Просмотр не вызывает `showResult` и не меняет ленту/исходный результат. Бэкенд повторно проверяет условия, а UI проверяет актуальность снимка.

root владеет Program.cs, ServerOptions.cs, TrackWorkshop.csproj, launchers, API/README/Deploy, ServerTests и STATUS. Backend владеет InputToleranceAnalysis.cs, Tests/InputToleranceChecks.cs и вызовом проверки в Tests/Program.cs (согласовать с search specialist, он этот файл не меняет); при необходимости WorkshopService.cs. UI владеет Web целиком. Search владеет RouteSearch.cs, DeveloperDocument.cs, Tests/RouteSearchChecks.cs. Общие файлы не редактировать одновременно.

## Уточнения, закрытые при проверке

Проверка не заканчивается на финише в воздухе, выдаваемом Core как завершение измерения полёта. Нужна настоящая опора. Если после ранней посадки неизменённая следующая команда опять поднимает героя до достижения исходного X, ожидается следующая действительная посадка. Прерванный ударом полёт сохраняет свой взлёт через восстановление: проба не может замаскировать этот удар более поздней посадкой другой связки. Не достигнутый момент следующей команды при пропуске — `incomplete`, даже если забег уже финишировал. Очень большие допустимые времена не переполняют JSON-метрику интервала.

[Открыть эксперимент 0.5.17](http://127.0.0.1:4226/). [Прежняя 0.5.16](http://127.0.0.1:4224/) сохранена и проверена через healthz. Следующий шаг — пользовательская проба на своих уровнях. Сравнить обычный прыжок, связку с воздушным переворотом и раннюю посадку перед препятствием; сопоставить найденные точки с ручными попытками. Техническая приёмка не устанавливает субъективную трудность или достаточную длину передышки. Основная ветка не переключалась; для отказа достаточно продолжить пользоваться прежней мастерской. Временные пробы не сохраняются в JSON; сохраняются найденные поиском маршруты с их собственной сеткой и настройками.
