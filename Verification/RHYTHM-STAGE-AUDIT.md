# RHYTHM-01 — независимая проверка короткого участка

19 октября 2026. **Независимые CPU-проверки stage 2 и исправленного Flow прошли; Gate RH-01 ожидает браузер новой сцены.** Первый участок с offset 192 имеет сохранённый воспроизводимый recovery RED. Он заменён компактной геометрией 112; прежний браузерный успех маршрута 192 не выдаётся за проверку новой версии.

## Метод и снимки

[Tools/RhythmAudit](../Tools/RhythmAudit/README.md) использует production `Press` / `Advance`, самостоятельно рассчитанные интервалы по физическим прямоугольникам и собственный план нажатий. Авторские `SafeRoute` / `RiskRoute` не читаются. У Main в обычном oracle повтор через 0,18 с, у автора исходного участка — через 0,2 с. Два игрока проверяются независимо в одной симуляции.

Проверенный Core: `AA91B96919AE318607D8BFF180AE7A54879FA54C2C6072003F5B245A57E10C24`; `ObstacleGeometry`: `BB1A5F4F79981CCDF3DABC4E9DB0511C3F9D9247B9E712ACC3FABB717653B92B`. Исходный `TracksRhythm`: `84565BBC2DDB13C7F3FE39D453DB83CA9D9C429F649DA14A69883E5D6F21FD21`. Полные SHA всех прочитанных исходников сохранены в каждом stdout, проверены до и после исполнения. Историческая геометрия 192 также записана отдельной fixture в `RecoveryRed.cs`; её не заменяет новый candidate.

Проверка реальных переходов бонусов приведена отдельно в [RHYTHM-CORE.md](RHYTHM-CORE.md).

## RED: недостаточное расстояние после ошибки

[Точный Fast witness](rhythm-recovery-red.txt): собственный input 4 задержан на 0,64 с. Первый удар о gate 4 на X2308, центр Y226. После остатка штрафа и 150 мс реакции игрок находится на X2341. Перед следующей нижней полосой остаётся 55 единиц, то есть 0,25 с. Даже немедленный разрешённый переворот требует не менее **0,309328430 с** для нужного подъёма. Реальная симуляция подтверждает второй удар на X2396, Y132,875. Воздушный разворот уменьшил бы ускорение вверх и не устраняет этот дефицит.

Для позднего второго действия Main [карта необходимых ограничений](rhythm-recovery-spacing-map.txt) использует реальные состояния после реакции: Y166,025092 / VY+207,444562 и зеркало Y73,974908 / VY−207,444562, без опоры. Даже более благоприятная модель с мгновенным повтором после отскока от стены требует не менее 0,524577985 с. Необходимый pitch превышает **340,407157**, но это ещё не достаточное расстояние для полного следующего прохода.

| Соседние gate, индексы с нуля | Pitch 192-серии | Вывод для позднего Main |
|---|---:|---|

| 3 → 4 | 330 | Ниже необходимой границы |
| 4 → 5 | 280 | Ниже необходимой границы; также доказанный Fast RED |

| 6 → 7 | 320 | Ниже необходимой границы |

[Узкий sweep исторических состояний](rhythm-recovery-pitch-witnesses.txt) с шагом pitch 10 нашёл полноценные зеркальные пути при Fast 300 и Main 420. Это **найденные достаточные witnesses, не глобальные минимумы**. Main использует допустимое действие через 0,16 с после реакции, настоящую опору, затем самостоятельный oracle следующего прохода. Производственная геометрия при этом не менялась.

## Компактный candidate 112

Проверен отдельный fixture: width 16, offset 112, GapTop 110 / GapBottom 130. [Тот же класс поздних ошибок](rhythm-compact112-recovery.txt) даёт Main после реакции Y140,066784 / VY+92,943468 и зеркало, без опоры. Полный выход найден при pitch 250: действие сразу после штрафа +150 мс, следующий повтор через 0,4 с. Для Fast найден pitch 230. Обязательный повтор через 80 мс не вводился.

[Предложенная серия](rhythm-compact112-proposed-recovery.txt) X300/900/1500/1860/2230/2590/2960/3320, длина 3720: nominal обоих профилей прошёл шесть dt; **80 реальных состояний первого удара** (Fast 48, Main 32) имеют путь за следующий `unionRight + R + 1` после остатка штрафа и 150 мс реакции. По одному сдвигались действия на −640/−400/−160/+160/+400/+640 мс. В некоторых случаях Main сначала делает два действия с интервалом 0,18 с, достигает настоящей стены, затем проходит следующие ворота. Это конечная выборка и набор разрешённых стратегий, не гарантия для всех возможных ошибок.

## Stage 2 и исправленный Flow — текущий CPU checkpoint

`TracksRhythm.cs`: `8C77E83043D3A7CC3496B0206FD8D46DCFC9B0CD670F5527906F9C9890EF0E1C`. Помимо восьми компактных ворот, участок содержит прямой проход X3800 и низкий порог X4300, длина 4600. Низкая форма: нижняя часть высотой 16 первой, верхняя высотой 114 со смещением +80; обе шириной 16. `TracksFull.cs`: `901255021DD6069E43734E80D16B88E5DC82824CB973239A451D8999317FA576`; та же форма и зеркала восстановлены в Flow X300/1550/6400. Расписание компактной части и доступных прямого/низкого проходов рассчитано независимо; собственный Fast quick return использует повтор через **0,17 с**, начинается и заканчивается на полу. Отдельный optional Main witness с двумя коррекциями исполняется и возмущается независимо, но не заявляется как независимо открытый оптимальный путь. Flow использует авторские X-маршруты как witnesses, собственный scheduler фактической скорости и отдельные утверждения времени/эффектов; это также не заявка на независимое открытие маршрутов.

Для Flow каждый из 11 потенциальных обычных импульсов консервативно получает 198 единиц работы при максимальной обычной скорости 330. Геометрические release bounds используют правую границу **обеих** частей. Завершение всей этой работы не позже X7820,000001, запас до X7876 — почти 56 единиц. Любой subset ограничен случаем всех импульсов; recovery одновременно останавливает X и эффекты. Проверены фактически пустая очередь/связанные ожидания перед целью и отсутствие иных препятствий в последних 44 единицах.

Эти полные сценовые пути используют обычную скорость 220 без искусственных эффектов. Результат исходного stage 192 при удерживаемых 110/330 не переносится на stage 2: у прямых ворот Fast single-flip при постоянных 110 пути нет, для такой отдельной fixture требуется другая форма действий. Отдельные низкие формы и реальные переходы импульсов проверены автором Core; их scope следует читать в соответствующих engine-артефактах, не как независимый full-stage 110/330 PASS.

## Следующие обязательные проверки

[Уточнение по рисункам](../../flip-race/docs/flip-race-gate-shapes-correction-2026-10-19.md) прочитано вместе с обоими изображениями. Маленький нижний порог низкого прохода должен идти **первым**, длинная верхняя часть — позже. Оба тела физические и видимые. Fast quick return начинается и заканчивается на одной стене и использует только один воздушный повтор; доступный вход с противоположной стены и Main обычный прыжок проверяются отдельно.

Ожидается браузер формы и движения новой сцены в обеих половинах экрана, включая видимый заранее низкий порог и два разных пути. Исторические 192 PASS/RED и выпущенные сборки сохраняются. Оценка удобства человеком, физический телефон и multitouch этой CPU-проверкой не подтверждаются.

## Воспроизведение

Из корня `flip-race-unity`, PowerShell с доступным `Add-Type`:

```powershell
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope recovery-red
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope recovery-map
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope recovery-pitch
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope compact-proposed
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope two-band-penalty
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope parts
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope family-stage
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope family-recovery
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope restored-flow
pwsh -NoProfile -File Tools/RhythmAudit/Run.ps1 -Scope flow-recovery
```

`recovery-red` успешно воспроизводит **ожидаемый RED**, а не объявляет участок исправленным. `parts` обязан упасть, пока остаётся хотя бы одна отсутствующая часть. `Capture.ps1 -Scope <scope> -OutputPath Verification/<new-name>.txt` добавляет SHA; при ошибке PASS-файл не записывается. Исторические stdout не перезаписывать. `stage`, `stage-speeds`, `bypass`, `recovery` читают текущий `Practice`, поэтому ранние результаты привязаны к сохранённому SHA, а не автоматически относятся к будущей геометрии.
