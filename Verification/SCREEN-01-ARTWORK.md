| Фактическое состояние | Проверенная ветвь рисунка |
|---|---|
| Available, включая пропущенный без контакта объект | Личная метка остаётся; кольцо не тускнеет |
| Collected/Pending | Метка контакта исчезает, объект остаётся видимым при pending или доступности второму. Pending сам не создаёт шлейф ускорения: он зависит от действующих `BoostRemaining` / `FinishBoost` |
| Failed | Приоритет перед Collected; личная метка не возвращается. Объект для второго остаётся прежней яркости и цвета типа |
| Successful / Negative | Пропадает только знак этого игрока; два состояния читаются независимо. Когда оба израсходовали объект, обычный объект может исчезнуть |
| Landing | Физическая rail всегда видима; остаётся яркой, пока награда доступна хотя бы одному. После расходования обоими используется прежний рисунок израсходованной площадки, без удаления опоры |
| Finish | Та же стрелка11×16, вершина на точной плоскости X/Y, реальные границы `FinishHeight`; личные метки независимы |
| Личный удар | Общие камни и обе части ворот получают `hit=false`; чужая геометрия не становится прозрачной. Личная реакция рисуется возле героя |

Обычное положительное кольцо сохраняет золотой «+», отрицательное — лиловый ромб с «−», instant — бирюзовую молнию. Цвет самого объекта не заменяется цветом оставшегося игрока. Фиксированные owner-слоты используют круг/лаванду и ромб/персик. Ожидание подтверждения не окрашивается как выданное ускорение.

При defaultHalf размеры получены из тех же `ScaleX`, `ScaleY` и примитивов, что и прежняя одиночная lane. Для568×320 фактическое поле550×132.5: малый камень25.215×21.3px, большой78.796×40.825px, метки32/52 дают12.607/20.487px, ring radius6.5px, герой radius7.5px, окно finish16 даёт7.1px. Для1280×720 поле1190×201.6: соответственно40.966×32.659,128.020×62.597,20.483/33.285,8.1648,9.5256 и10.8864px. Камера меняет X-положение, а не этот масштаб. Общие центры героев остаются точной общей проекцией, без личного отражения или bob центра.

Просмотрены настоящие PNG `screen-stage1-fast-asym-start`, `-personal`, `-hit`, `-firstfinish`: различимы оба знака при совпадении, личный сбор на площадке, сохранённый общий камень после удара и открытое поле после первого финиша. На этих исторических кадрах ещё показано старое положение HUD; root уже вынес его наружу в текущем source. Эти четыре кадра не объявляются пиксельной проверкой всех pending/failed/negative переходов: для них проверены реальные renderer-ветви и отдельный независимый Core/projection audit delivery.
