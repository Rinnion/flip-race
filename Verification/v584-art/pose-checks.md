# 5.8.4-trial — проверка кадров катикаавров

Статус: PASS на штатном растеризаторе MascotArtwork под настольной .NET 10 с заменителем графического API Unity. Критерий R-02 в [STATUS](../V584-ROSTER-STATUS.md); правила и рамки приёмки — [графика Flip Race](../../../flip-race/docs/flip-race-art-direction.md), [VIEW](../../../flip-race/docs/features/race-views.md) и [TOUCH](../../../flip-race/docs/features/touch-and-selection.md). Исходные рисунки Тани и адаптация описаны в [README](README.md).

- **Старые герои:** 4 608 кадров и 24 портрета попиксельно совпадают с `ef4873c` по SHA-256 RGBA. Это все 192 фазы для каждого героя в четырёх слотах; отдельно проверено по 64 вызова публичного селектора движения на каждую пару «старый герой / слот». Эталон извлечён из Git, отдельно скомпилирован с историческим составом.
- **Новые герои:** 3 072 кадра без выхода на внешнюю границу текстуры 128×128; на наиболее тесном кадре остался 1 прозрачный пиксель до края. Для каждого героя и слота каждый набор движений содержит минимум три разных кадра. В окне лица 48×24 осталось как минимум 749 непрозрачных пикселей, при моргании в окне левого глаза изменилось не менее 83 пикселей. Это геометрические признаки читаемости, но художественную оценку и размер на экране они не заменяют.
- **Все 10 героев:** 40 портретов; каждый из десяти в одном слоте отличим по содержимому текстуры, а у каждого из четырёх новых проверены четыре разные расцветки слотов.
- **Кэш:** создание портрета добавляет одну текстуру, подготовка слота — ни одной текстуры движения, первый запрос кадра — одну. По 10 000 повторов одного бегового кадра на каждый новый образ/слот дали одинаковый объект, 0 новых текстур и 0 байт управляемых выделений. Максимум в этом настольном прогоне: 18,80 мс на первый портрет, 3,15 мс на первый кадр движения после подготовки слота. Время подготовки слота и фактическая задержка интерфейса здесь не измерялись.

Листы: [все 40 портретов](all-previews.png), [Нико](69-niko-poses.png), [Игри](68-igri-poses.png), [Шедоу](48-shadow-poses.png), [Пушинка](38-pushinka-poses.png). Строки — слоты 1–4. Для каждого нового героя пары столбцов — обычный кадр и поворот на 180° для общего поля, в порядке: ожидание, моргание, бег, воздух, восстановление, успешный бег, победа. На листах — исходное разрешение текстуры; зеркалирование чужой дорожки, призрак, масштаб в гонке и фактический интерфейс проверяются в WebGL отдельно. Листы не означают художественного одобрения.
